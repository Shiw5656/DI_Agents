# Canonical Data Model Recommendation

## 1. Recommended Data Domains

### **Student Management**
**Description:** This domain focuses on managing student information, academic attributes, enrollment data, attendance tracking, and programme participation.

---

### **Teacher Management**
**Description:** Includes information about teacher identities, roles, and their assignments to course sections.

---

### **School Administration**
**Description:** Captures school-specific data, including school profiles, authorized programmes, and operational details.

---

### **Academic Offerings**
**Description:** Provides structure for academic programmes, courses, course offerings, and related metadata.

---

### **Assessment Tracking**
**Description:** Manages assessment details, results, and performance summaries.

---

### **Attendance Management**
**Description:** Covers detailed attendance records for students across academic terms and sections.

---

## 2. Recommended Entities by Domain

### **Student Management**

| Entity Name                  | Entity Description                                                 |
|------------------------------|---------------------------------------------------------------------|
| Student                      | Represents a student.                                              |
| Student Personal Details     | Personal attributes of a student, including PII.                  |
| Student Academic Details     | Academic attributes such as enrollment status and grade levels.   |
| Programme Participation      | Tracks student participation in specific IB programmes.           |

---

### **Teacher Management**

| Entity Name                    | Entity Description                                          |
|--------------------------------|------------------------------------------------------------|
| Teacher                        | Represents a teacher.                                      |
| Teacher Details                | Includes teacher-specific information like departments and certifications. |

---

### **School Administration**

| Entity Name                | Entity Description                              |
|----------------------------|------------------------------------------------|
| School                     | Represents an IB school.                      |
| School Profile             | Details about authorized programmes and school location. |

---

### **Academic Offerings**

| Entity Name               | Entity Description                           |
|---------------------------|-----------------------------------------------|
| Academic Programme        | Represents IB programmes like PYP, MYP, etc. |
| Course                    | Represents a course.                         |
| Course Section            | Represents specific sections tied to terms.  |

---

### **Assessment Tracking**

| Entity Name              | Entity Description                                    |
|--------------------------|-------------------------------------------------------|
| Assessment               | Represents an assessment event (e.g., TOK Essay).     |
| Assessment Results       | Contains student-specific assessment results.         |

---

### **Attendance Management**

| Entity Name                  | Entity Description                                            |
|------------------------------|--------------------------------------------------------------|
| Attendance Events            | Represents attendance events for students in course sections.|
| Attendance Status Reference  | Reference table for attendance codes such as 'P' (Present). |

## 3. Assumptions and Limitations

1. **Profiling Completeness:** The profiling data is based on synthetic samples, limiting validity for the production dataset.
2. **Metadata Missing:** Documentation lacks clarity on historization rules for overlapping or future date consistency.
3. **Business Definitions Incomplete:** Specific domain boundaries and functional purposes need refinement and stakeholder input for validation.
4. **Constraints Required:** Anomalies, such as invalid grades and negative section capacities, indicate the need for tightened constraints on data.
